# 執事が家を片づける

床板の下の家事を、きちんと済ませた。それで家は前よりまっすぐに立つ。Android と Windows は共有する論理を一つのソースツリーから取るようになり、インストーラーは空模様を読んでから慌てるかどうかを決めるビルドに見守られ、両プラットフォームは同じバージョン番号を名乗る。ここに新しく見つけるものは何もなく、頼れるものはいくらか多い。パッチリリースとは本来そういう形のものだ。床板は堅い。これがその土台の上で作られた最初のリリースである。

**一つの心臓が、いま二つのプラットフォームに仕える。** 七十八の共有ソースファイル——業務ロジックと界面の大部分——は一つのモジュールにだけ置かれ、Android アプリと Windows インストーラーの双方がそれをコンパイルする。そこを一行直せば、同じコミットで両プラットフォームが直る。だから二つが食い違うことはない。一致は保守する者の習慣ではなく、ビルドの性質である。プラットフォームの継ぎ目はあるべき場所、それぞれのツリーに残る。Room と JDBC、JNI と DLL のネイティブブリッジ、Android 側の詰め物、そして Activity と Desktop の殻。各プラットフォームは本当に自分のものだけを抱え、それ以外のすべては同じ一冊からコンパイルされる。

**ビルドは空模様を読む。** 2026 年 9 月 2 日、三つの成果物リポジトリ——Google Maven、Maven Central、Gradle Plugin Portal——が Windows ランナーからおよそ十三分のあいだ到達不能になった。いまは予熱の段階が各結果をそれぞれのログの文面から見分ける。ネットワークとリポジトリの印には、待ち時間を段階的に延ばしながら最大六回の試行を与え、その合計はこれまでに観測されたどの障害よりもはるかに長い。本物のビルドの問題は、再試行の下に埋もれず、その場で報告される。いつ待ち、いつ止めるかを知っているパイプラインである。再試行の方針はワークフローそのものに記され、その理屈は、それを実行するコードとともに歩く。

**数字は一致し、インストールは落ち着く。** 両プラットフォームは同じ利用者向けバージョンを名乗り、デスクトップパッケージのバージョンもそれに連れて上がる。だから Windows へのインストールは、後継の隣に並ぶのではなく、その場で更新される。バージョンは一か所に刻まれ、二台の機械で読まれる。どちらのプラットフォームも黙って遅れることはなく、インストーラーは自分が置き換える側を見分ける。APK とインストーラーを生み出すワークフローはリポジトリの中にあり、ビルドに手が要るときは原因を正確に名指しする。このリリースがどう作られたかを知りたい者は、手順どおりに追えばよい。作り方は箱の中に置かれたままで、必要な者はいつでも開いて読める。

起動はどちらのプラットフォームでも同じに振る舞い、片方に加えた機能は同じ息で片方にも届き、あなたが見張っておくものは何も残らない。執事は灯りを消したまま家を片づけ、すべては明朝あるべき場所にある。それが約束のすべてであり、それは守られている。
