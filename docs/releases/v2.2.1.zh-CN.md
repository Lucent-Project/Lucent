# 管家把屋子收拾了一遍

地板底下的家务，做得妥帖，房子于是站得更直。Android 与 Windows 如今从同一棵源码树里取用共有的逻辑，安装器由一条先看清天气再决定慌不慌的构建守着，两个平台报出同一个版本号。这里没有新东西等着你去发现，可依赖的东西则多了不少，这正是一个补丁版本该有的样子。地板是结实的。这是建立在那套地基上的第一个版本。

**一颗心脏，如今供两个平台使用。** 七十八个共享源文件——业务逻辑与大部分界面——只存在于一个模块里，Android 应用与 Windows 安装器都编译它。在那里改一处，同一个提交里两个平台就都改了，两者因此无法各走各的；一致是构建的属性，而不是维护者的习惯。平台的接缝留在它们该在的地方，各自的树里：Room 对 JDBC，JNI 与 DLL 原生桥接，Android 那边的垫层，以及 Activity 与 Desktop 的外壳。每个平台只留下真正属于自己的部分，其余的一切都从同一份文稿编译出来。

**构建会先看天气。** 2026 年 9 月 2 日，三个构件仓库——Google Maven、Maven Central 与 Gradle Plugin Portal——从 Windows 运行器上都无法访问，大约持续了十三分钟。如今的预热步骤会从各自的日志文本判断每一次结果：网络与仓库的标记最多换来六次尝试，退避逐步拉长，总时长远远超过已观察到的任何一次中断；而真正的构建问题会立刻报出来，不会埋在重试底下。一条知道何时该等、何时该停的流水线。重试策略写在 workflow 本身里，于是那套道理跟着执行它的代码一起走。

**数字对得上，安装也安定下来。** 两个平台报出同一个面向用户的版本，桌面安装包的版本随之一起升，于是一次 Windows 安装是在原地升级，而不是与它的后继者并排站着。版本只在一处打上，却要在两台机器上读取，所以哪个平台都无法悄悄落在后面，安装器也认得自己正在替换的那一份。产出 APK 与安装器的 workflow 就在仓库里，构建需要有人过问时，它会准确指出原因。想知道这次发布是怎么做出来的，可以一步步照它看下去。配方留在盒子里，谁需要都能打开读。

一次启动，两个平台表现相同；给一个平台添的功能，同一口气里就到了另一个平台；没有什么需要你盯着。管家关了灯把屋子收拾好了，一切都待在明天早晨它该在的位置。这就是承诺的全部，而它兑现了。
