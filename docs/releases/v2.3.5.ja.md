# ひとつのコードベース、2台のマシンがすべてに同意する

このリリースは、Lucentが何をするかと同じくらい、どう組まれているかについてのものだ。家は内側から外側へ片づけられ、ツールチェーンは最新の公式版へ移り、共有モジュールはいまやAPKとWindowsインストーラの両方へコンパイルされる。最初に気づく変化は控えめで心地よい。ひとつのチャットメッセージが、複数のファイルを一度に運べるようになった。

**メッセージが運ぶのはひとつではなく、いくつかのファイル。** 写真とPDFとノートを一度に選べば、コンポーザーの上で整ったファイル名チップの帯に並び、どれもワンタップで外せる。AndroidはGetMultipleContentsとOpenMultipleDocumentsを通じて一組をまとめて受け取り、デスクトップは選ぶたびにひとつを積み上げる。送れば、それぞれのファイルが会話の中で自らの小さな名前の行として現れ、タップすればビューアが開き、その一組は再送、返信のダウンロード・ダイアログ、ノートへの保存、書き出しzipをそのまま通り抜ける。データベースはv15からv16へ移り、nullableなJSONカラムをひとつ得た。3つの旧来の添付カラムは最初のファイルを保つので、以前のどの行もこれまでどおりに読める。

**目録はひとつ、真実の源もひとつ。** インターフェースの文字列は、単一の共有i18nカタログに住む。4つの言語、ひとつのファイル、そして新しい文字列はただ一度だけ加えられる。残っていたバイト単位で同一の双子のコードは共有モジュールへ統合され、データ消去のルーチンはひとつ、タグのパーサもひとつ、翻訳表も手作業で歩調を合わせる2つではなく4言語のひとつになった。その結合はどちらの側も参照する鍵をすべて保ち、生成器は共有ツリーの期待する配置でファイルを書く。プラットフォームが本当に異なるところ——Roomに対するJDBC——では、継ぎ目は短く、意図的で、その隣のツリーに記されている。

**ツールチェーンは最新で、ネイティブの段階は任意の客だ。** Gradle 9.7.1、AGP 9.4.0、Kotlin 2.4.0、KSP 2.3.11、Compose Multiplatform 1.12.0、NDK 28.2、API 37に対してコンパイルし、共有ソースツリーは`kotlin.srcDir`を通じてビルドに接続される。ネイティブの段階——llama.cppエンジン、Rustアクセラレータ、Windowsインストーラのパッケージング——はそれぞれ独立して立つので、どれかひとつがしゃっくりをしても、待合室ではなく動くアプリが手元に残る。デスクトップはAndroidがネイティブに備えるAPIのために小さなプラットフォーム・シムを携え、両方のビルドは同じ共有ソースを読む。

**依存は意図をもって留められ、継ぎ目は書き留められている。** 最新のandroidxとhazeのアーティファクトは、SDKチャネルがどのランナーでもまだ提供していないコンパイル対象を求める。そこでプロジェクトは、各マシンがインストールできるプラットフォームに対してコンパイルできる最新の版にライブラリを留める——そしてその理由は、その選択をしたコミットの中に生きている。デスクトップ側の更新も同じ回に届く。coroutines 1.11、okhttp 5.5、org.json 20260814、pdfbox 3.0.8、sqlite-jdbc 3.53.4.0。短い文書が、ツールチェーンの版、i18nの単一拠点の取り決め、そして設計上なお残る2つのプラットフォームの継ぎ目を記録するので、次の読み手は好奇心ではなく知識を持って始める。

ここはLucentの人生の心地よい中ほどだ。機能は見出しであることをやめるほどに成熟し、ツールチェーンは最新で、機能は翻訳と信頼ではなくコンパイルによってプラットフォーム間を移る。ひとつのコードベース、2台のマシン、そして疑うべきものは何も残っていない。
