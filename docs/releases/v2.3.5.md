# One Codebase, Two Machines Agree on Everything

This release is about how Lucent is built as much as what it does. The house has been tidied from the inside out, the toolchain moved to the newest official versions, and the shared module now compiles into both the APK and the Windows installer. The change you will notice first is modest and pleasant: a chat message can carry several files at once.

**A message carries a handful of files, not one.** Pick a photo, a PDF and a note in a single pass, and they queue into a tidy strip of filename chips above the composer, each removable with one tap. Android takes the whole set at once through GetMultipleContents and OpenMultipleDocuments; the desktop accumulates one per pick. Send, and each file appears as its own compact name row in the conversation, a tap opens the viewer, and the set travels intact through resend, the reply download dialog, save-into-a-note and the export zip. The database moved from v15 to v16 with a nullable JSON column; the three legacy attachment columns keep the first file, so every earlier row reads as it always did.

**One catalogue, one source of truth.** The interface strings live in a single shared i18n catalogue: four languages, one file, and a new string is added exactly once. The two byte-identical code twins that remained were merged into the shared module, leaving one data-wipe routine and one tag parser, and one translation table in four languages rather than two keeping pace by hand. The union keeps every key either side references, and the generator writes the file in the layout the shared tree expects. Where a platform genuinely differs — Room against JDBC — the seam is short, deliberate and documented in the tree beside it.

**The toolchain is current, and the native stages are optional guests.** Gradle 9.7.1, AGP 9.4.0, Kotlin 2.4.0, KSP 2.3.11, Compose Multiplatform 1.12.0 and NDK 28.2, compiling against API 37, with the shared source tree joined to the build through `kotlin.srcDir`. The native stages — the llama.cpp engine, the Rust accelerator and the Windows installer packaging — each stand on their own, so a hiccup in any one of them leaves you with a working app rather than a waiting room. The desktop carries small platform shims for the APIs Android ships natively, and both builds read the same shared sources.

**The dependencies are pinned deliberately, and the seams are written down.** The newest androidx and haze artefacts ask for a compile target the SDK channels do not yet serve on every runner, so the project holds its libraries at the newest versions that compile against the platform each machine can install — and the reason lives in the commit that made the choice. Desktop-side upgrades arrive in the same pass: coroutines 1.11, okhttp 5.5, org.json 20260814, pdfbox 3.0.8 and sqlite-jdbc 3.53.4.0. A short document records the toolchain versions, the single-point i18n arrangement and the two platform seams that remain by design, so the next reader starts informed rather than curious.

This is the comfortable middle of Lucent's life. The features are mature enough to stop being headlines, the toolchain is current, and functionality moves between platforms by compilation rather than by translation and trust. One codebase, two machines, and nothing left to mistrust.
