# 一套代码，两台机器，处处一致

这次发布关于 Lucent 如何被建造，同样关于它能做什么。这座房子从里到外被收拾过一遍，工具链移到了最新的正式版本，而共享模块如今同时编译进 APK 和 Windows 安装程序。你最先注意到的变化朴素而愉快：一条聊天消息可以一次带上好几个文件。

**一条消息带上几个文件，而不是一个。** 一次挑好一张照片、一份 PDF 和一条笔记，它们便排成一条整齐的文件名标签带，停在输入框上方，每一个都能轻点一下移除。Android 通过 GetMultipleContents 与 OpenMultipleDocuments 一次收下整组；桌面端则每选一次积累一个。发送之后，每个文件在对话中各自成为一个紧凑的名字行，点一下便打开查看器，而这一组文件在重发、回复下载对话框、存入笔记和导出 zip 之中都原样通行。数据库从 v15 移到 v16，增加了一个可为空的 JSON 列；三个旧有的附件列保留第一个文件，所以此前每一行读起来都和从前一样。

**一份目录，一个真理之源。** 界面字符串住在唯一一份共享的 i18n 目录里：四种语言，一个文件，新增一条字符串只需添加一次。仅存的两份逐字节相同的代码孪生子被并入共享模块，于是只剩下一套数据清除例程、一个标签解析器，以及一张四种语言的翻译表，而不必再让两张表手工彼此追赶。合并后的并集保留了任何一侧引用过的每一个键，生成器写出的文件也符合共享目录树所期望的版式。在平台确实有别的地方——Room 对 JDBC——接缝很短，是刻意留下的，并且就在它的旁边写进了代码树里。

**工具链是最新的，而原生阶段是可选的客人。** Gradle 9.7.1、AGP 9.4.0、Kotlin 2.4.0、KSP 2.3.11、Compose Multiplatform 1.12.0 与 NDK 28.2，针对 API 37 编译，共享源码树通过 `kotlin.srcDir` 接入构建。原生阶段——llama.cpp 引擎、Rust 加速器和 Windows 安装程序打包——各自独立，所以其中任何一个打个嗝，你拿到的仍是一款能用的应用，而不是一间候诊室。桌面端为 Android 原生自带的那些 API 备了小小的平台垫片，两份构建读取同一批共享源码。

**依赖是刻意钉住的，接缝是写下来的。** 最新的 androidx 与 haze 制品要求的编译目标，SDK 渠道尚未在每一台运行机上提供，于是项目把库停在每一台机器都能安装的平台之上仍可编译的最新版本——而其中的理由就住在做出这个选择的那次提交里。桌面端的升级在同一趟里抵达：coroutines 1.11、okhttp 5.5、org.json 20260814、pdfbox 3.0.8 与 sqlite-jdbc 3.53.4.0。一份短短的文档记录下工具链版本、单点式的 i18n 安排，以及按设计仍然留下的两处平台接缝，于是下一位读者带着所知开始，而不是带着好奇。

这是 Lucent 一生中舒服的中段。功能成熟得足以不再当标题，工具链是最新的，而功能在平台之间移动靠的是编译，而不是翻译与信任。一套代码，两台机器，没有什么还需提防。
