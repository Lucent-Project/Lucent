# The Background Runs Its Own Race

Two phone screenshots and one long press account for most of this release, which is a reasonable way for a version to spend its time. The confirmation dialog's three decisions sit on a single row, "keep refining" has a defined procedure with its follow-up question written by the app itself, every template chip belongs to one family with a menu behind a long press, and the Android background runs on a renderer with its own thread and its own clock.

**One row, three decisions.** The assistant's confirmation dialog now carries refine, add and cancel on one line on every device, with every label at full size: the padding between the labels is tightened, the font stays at its natural size, and maxLines=1 stands guard. The row reads left to right in the order the decision works — refine it, add it, or do not. Narrow displays get the same single row as wide ones, which is the point of a decision line: one glance, three choices, no scrolling. Nothing is abbreviated to make the row fit.

**"Keep refining" means what it says.** Choosing to refine writes nothing at all. The follow-up question is composed by the app, in your own language, and your answer rides into the next turn with the parked proposal attached to the system prompt, so the assistant re-proposes the item with your adjustments and calls its tool again. The confirmation dialog then returns with the revised item, because the final yes is always yours. The same procedure runs on the cloud path and the on-device path, so the behaviour does not depend on which model is answering. A refine is a conversation, and it now has turns.

**One family of chips, one menu behind them.** Every chip in the template strip — built-in and custom alike — is a real FilterChip, so colour, size, corner radius and baseline agree by construction on any theme. A long press opens Edit and Delete for both families: built-ins can be hidden, the hiding persists, and a hidden built-in can be restored from the strip; custom templates open in edit mode and save back onto themselves; and a built-in's shape can be loaded and saved as your own. The strip behaves like one thing because it is one thing.

**A background with its own thread.** On Android the background renders entirely apart from the interface: a renderer on its own worker thread rasterises each frame, on its own clock, into a double-buffered half-resolution bitmap, and the UI thread performs one cheap textured draw. Page transitions cannot starve the animation, because no animation competes with them for the page thread. The motion math, the morph, the squash and the spin are unchanged, the adaptive tiers still apply, and the field rests when the app does. The new-tag field, meanwhile, is a tidy 0.8 of its default height, centred.

Windows keeps the shared, GPU-backed path, because the isolation is a phone's answer to a phone's problem. All four languages carry the new strings, hidden templates travel in the backup's settings block, and the unit tests still run on every build. The background runs its own race; the interface is free to run yours.
