# 后台跑自己的比赛

两张手机截图和一次长按，构成了这个版本的大部分内容——一个版本这样花时间，也算合理。确认对话框的三个决定落在同一行上，“继续打磨”有了一套明确的流程，后续问题由应用自己写成；每一枚模板标签都属于同一个家族，长按之下有一个菜单；Android后台跑在一个有自己线程、自己时钟的渲染器上。

**一行，三个决定。** 助手的确认对话框如今在每一台设备上都把打磨、添加、取消放在一行里，每个标签都是完整字号：标签之间的间距收紧了，字体保持它自然的大小，maxLines=1守着这一行。这一行按决定发生的顺序从左到右读——打磨它、添加它，或者算了。窄屏与宽屏拿到同样的一行，这正是决定行的意义：一眼、三个选择、不需要滚动。为了让这一行放得下，没有任何东西被缩写。

**“继续打磨”说到做到。** 选择打磨不会写入任何东西。后续问题由应用用你自己的语言写成，你的回答带着停在原处的提案一起进入下一轮——提案附在系统提示上——于是助手按你的调整重新提出这一项，并再次调用它的工具。随后确认对话框带着修订后的条目回来，因为最后的“是”永远属于你。同一套流程跑在云端路径和设备内路径上，所以行为不取决于由哪个模型作答。打磨是一场对话，而它现在有了轮次。

**同一个家族的标签，它们身后是同一个菜单。** 模板条上的每一枚标签——内置的和自定义的一样——都是真正的FilterChip，因此颜色、尺寸、圆角与基线在任何主题下都天生一致。长按为两个家族打开“编辑”与“删除”：内置模板可以隐藏，隐藏会持续，被隐藏的内置模板可以从模板条恢复；自定义模板以编辑模式打开，并存回自身；内置模板的形状可以被载入，并保存成你自己的。模板条之所以像一件事物，因为它就是一件事物。

**一个有自己线程的后台。** 在Android上，后台完全在界面之外渲染：一个渲染器在自己的工作线程上，按自己的时钟，把每一帧光栅化进双缓冲的半分辨率位图，界面线程只做一次廉价的纹理绘制。页面转场无法饿死动画，因为没有动画与它们争抢页面线程。运动数学、形变、挤压和旋转都没有改变，自适应档位照旧生效，应用停下时这一片也随之安歇。与此同时，新标签输入框正是它默认高度的0.8，居中。

Windows保留共享的、由GPU支撑的路径，因为这种隔离是手机对手机问题的回答。四种语言都带上了新字符串，被隐藏的模板随备份的设置块一起旅行，单元测试照旧在每次构建时运行。后台跑自己的比赛；界面则可以空出来跑你的。
