# ローカルモデルが道具を使えるようになる

ローカルのアシスタントは、語るのではなく、実際にそれをやれるようになった。ノートを整理してほしい、タスクを作ってほしい、検索を走らせてほしいと頼めば、自分で道具を選び、呼び出し、結果を読み返し、同じタスクの次の段階へ進む。道具の呼び出しが解釈できないときは、そうとはっきり言う。四つの備えがそれを頼りになるものにし、同梱のエンジンは二年分の上流の仕事を追い越して b11057 へ進んだ。道具箱は今、それを持つモデルの手の届くところに本当にある。

**そのまま届く道具。** プロトコルはプロンプトの末尾に置かれる。切り詰めの手が最後に届く場所なので、モデルが探しに行くときにも指示はそこに残っている。ローカルの道具一覧は、一つにつき一段落ではなく一行なので、目録は使える空間に収まる。会話は送られる前にエンジンの予算に合わせて刈り込まれるため、履歴が規則を押し出してしまうことはない。道具の結果は、プロンプトが求める形式のごく普通のユーザーメッセージとして戻ってくるので、タスクの二段目は同じターンに収まり、どの呼び出しにも結果が記録される。

**新しいエンジン、変更はきっかり三つ。** 同梱のエンジンは llama.cpp の **b9888** から **b11057** へ進む。それに必要な API の変更はきっかり三つだった。mmap フラグは読み込みモードになり、マルチモーダルの補助関数はオプション引数を得て、マルチモーダル入力のテキストは `strlen` で測られる代わりに自分の長さを持つようになった。新しい上流のハッシュ依存も一緒に組み込まれる。どちらのビルドもエンジンを同じ改訂に固定し、同じ CMake ファイルから先読みするので、Android と Windows は一つのエンジンを分け合って出荷される。デスクトップの GPU エンジンも CPU 側と同じ 4096 のコンテキストを持ち、収まらないプロンプトはログでそうとはっきり言う。

**ささやかな恵みを、正しい場所に。** 外観ページでは Material You がテーマと背景の上に戻り、テーマの説明は自分の色だけを述べ、明るいか暗いかを繰り返したりしない。内蔵の API プロバイダーは必要なものだけを尋ねる。住所欄が出るのは Custom だけで、しかも空の状態から始まる。添付の行は期限の行ときっかり揃い、ローカルモデルの項目はどの端末でも出される。戻るはエディタを離れる。ノートやタスクを編集で開いているとき、戻る操作は元いた一覧へ連れ戻す。ドラッグは指にきっかり従い、一覧を端まで横切る。行き先のない長押しは痕跡を残さない——暗くもならず、浮きもせず、影も落ちず、あとで片付けるものも何もない。

ローカルモデルのモジュールの外側に変える必要は何もない。そこが要点である。クラウドの経路、道具そのもの、そしてあなたのデータは、この移行には含まれていない。あなたのスマートフォンのアシスタントは手引きを読み、道具を選び、頼まれた仕事を最後までやり切る。
