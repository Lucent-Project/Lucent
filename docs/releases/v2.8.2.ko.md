# 로컬 모델이 도구를 쓰는 법을 배우다

로컬 어시스턴트가 이제 그것을 설명하는 대신 실제로 해낸다. 노트를 정리해 달라, 할 일을 만들어 달라, 검색을 돌려 달라고 하면 스스로 도구를 고르고, 호출하고, 결과를 읽어 되받은 뒤 같은 작업의 다음 단계로 이어 간다. 도구 호출이 해석되지 않으면 그렇다고 분명히 말한다. 네 가지 배치가 그것을 믿을 만하게 만들고, 함께 들어 있는 엔진은 2년치 업스트림 작업을 건너뛰어 b11057로 올라선다. 도구함은 이제 그것을 쥔 모델의 손이 닿는 곳에 진짜로 있다.

**온전히 도착하는 도구.** 프로토콜은 프롬프트 끝에 자리한다. 잘림이 가장 나중에 닿는 곳이라, 모델이 그것을 찾으러 갈 때도 지시는 그대로 남아 있다. 로컬 도구 목록은 도구마다 문단 하나가 아니라 한 줄이어서, 목록이 쓸 수 있는 공간 안에 들어간다. 대화는 보내지기 전에 엔진의 예산에 맞춰 잘려 나가므로, 기록이 규칙을 밀어내지 못한다. 도구 결과는 프롬프트가 요구하는 형식의 평범한 사용자 메시지로 돌아오므로, 작업의 두 번째 단계가 같은 턴에 들어오고, 모든 호출에 결과가 기록된다.

**더 새로운 엔진, 그리고 정확히 세 가지 변경.** 함께 들어 있는 엔진이 llama.cpp의 **b9888**에서 **b11057**로 올라간다. 여기에는 정확히 세 가지 API 변경이 필요했다. mmap 플래그는 로드 모드가 되었고, 멀티모달 도우미는 옵션 인자를 얻었으며, 멀티모달 입력 텍스트는 이제 `strlen`으로 재는 대신 스스로 길이를 지닌다. 새로운 업스트림 해시 의존성도 함께 링크된다. 두 빌드 모두 엔진을 같은 리비전에 고정하고 같은 CMake 파일에서 미리 가져오므로, Android와 Windows가 하나의 엔진을 나눠 갖고 출시된다. 데스크톱 GPU 엔진도 CPU 쪽과 같은 4096 컨텍스트를 얻었고, 들어가지 않는 프롬프트는 로그에서 그렇다고 분명히 말한다.

**작은 자비를, 제자리에.** 외형 페이지에서 Material You는 테마와 배경 위로 돌아가고, 테마 설명은 자기 색만 말하며 밝은지 어두운지를 되풀이하지 않는다. 내장 API 제공자는 필요한 것만 요구한다. 주소 입력란은 Custom에만 나타나고, 그것도 빈 상태로 시작한다. 첨부 행은 이제 마감일 행과 정확히 맞고, 로컬 모델 항목은 모든 기기에서 제공된다. 뒤로 가기는 편집기를 떠난다. 노트나 할 일을 편집 중으로 열어 둔 상태에서 뒤로 제스처를 쓰면 원래 있던 목록으로 돌아간다. 끌기는 손가락을 정확히 따라가며 목록 끝까지 이어지고, 아무 데도 닿지 않는 길게 누르기는 흔적을 남기지 않는다—어두워지지도, 떠오르지도, 그림자가 지지도 않고, 나중에 닫을 것도 없다.

로컬 모델 모듈 바깥에서는 바뀌어야 할 것이 없다. 그게 핵심이다. 클라우드 경로와 도구 자체, 그리고 당신의 데이터는 이번 이동에 포함되지 않았다. 당신의 휴대폰에 있는 어시스턴트는 설명서를 읽고, 도구를 고르고, 요청받은 일을 끝까지 해낸다.
