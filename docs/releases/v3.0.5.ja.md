# 工具箱は跳ぶ前に確かめ、Termux は正式に紹介される

Lucent 3.0.5 は小さなリリースですが、考えは大きなひとつです。プラグインの導入が信仰の跳躍であってはならない、ということ。工具箱はこれから、一バイトたりとも落とす前にすべてのプラグインを点検し、何が邪魔をしているのかを正確に伝え、どかし方まで教えます。あなたの言語で、いつもの乾いた落ち着きとともに。

**盲目的な跳躍ではなく、出発前の点検を。** 導入はすべて点検から始まります。アシスタントには新しい道具 `plugin_inspect` が加わり、プラグイン設定画面もインストールボタンを出す前に同じ点検を行います。行く手を阻むものがあれば——この機種向けの導入手順がない、配布元がない、ミラーがどれも無応答、フォルダに書き込めない、Termux が仮置きファイルを読めない、そもそも使えるシェルがない——失敗してから肩をすくめるのではなく、前もって理由と具体的な修復手順を示します。問題には固有の番号がつくので、アシスタントと設定画面はつねに同じ状況を同じ言葉で語ります。

**Termux、改めてご紹介。** Android での導入失敗のほとんどは、実のところ Termux の紹介が一度も行われていなかったことにありました。Lucent はこれから、導入の前に Termux のパッケージ一覧をひと作業ごとに一度更新します。名物だった "unable to locate package" の謎はこれで退役です。シェルそのものが不在の場合は、案内もようやく具体的になりました。F-Droid から Termux を入れ、一度開き、`termux-setup-storage` を実行し、`~/.termux/termux.properties` に `allow-external-apps=true` を設定、Android に求められたらコマンド実行の権限を許可する。Termux がまったく応答しない場合は、一部の派生版ではパッケージ名が異なることにも触れるようになりました。夜を救うのは、こういう細部です。

**覚えているダウンロード。** 選んだ最速のミラーが、今度こそ実際に使われます——以前は設定だけ保存されて、丁重に無視されていました。ダウンロードが中断しても、仮置きファイルが無事なら次回はそれを使い回し、取り直しはしません。小さな記録が各導入の到達点を書き留めるので、再試行は最初からではなく続きから始まります。ミラーが公称と異なる大きさのファイルを送ってきた場合は、ミラー側が画像を更新しただけかもしれないと伝え、別の配布元を指し示します。

**説明するアシスタント。** `install_plugin` は先に点検を行い、半ばで失敗する代わりに理由を添えて辞退します。進捗の表示は最初のバイトから始まり、二割まで待たされません。Termux がパッケージを見つけられないときは、パッケージ一覧が古かったのだろうと説明します——Lucent が自動で更新するようになったことも添えて。

**静かな記録。** 操作ログは、書き出す前に秘密の鍵らしい値や URL に埋め込まれた認証情報を塗りつぶします。誰にも読まれるはずのなかったものは、これからも読まれません。

Lucent の見た目は少しも変わっていません。工具箱が、取扱説明書を読んだかのように振る舞うようになっただけです。
