# 工具箱先看再跳，Termux 终于得到正式介绍

Lucent 3.0.5 是一个小版本，装着一个大想法：安装插件不该是一次信仰之跃。现在，工具箱在下载任何字节之前都会先检查每个插件，明确指出挡路的是什么，并告诉你怎么搬开——用你自己的语言，带着一贯的沉稳耐心。

**先检查再动手，不再盲目一跃。** 每次安装都从检查开始。助手新增了 `plugin_inspect` 工具，插件设置页在显示安装按钮之前也会做同样的检查。如果有东西挡路——这个平台没有安装脚本、没有下载源、所有镜像都没有响应、文件夹写不进去、Termux 读不到暂存文件，或者根本没有可用的 shell——检查会提前说明，并给出具体的修复步骤，而不是下载失败后耸耸肩。每个问题都有固定的编号，助手和设置界面描述的是同一种情况，用的也是同样的说法。

**Termux，正式介绍一下。** 在安卓上，大多数插件安装失败，其实都是 Termux 这场介绍从未发生。Lucent 现在每次会话会在安装前刷新一次 Termux 的软件包列表，经典的 "unable to locate package" 之谜就此退役。如果 shell 完全缺席，指引终于具体了：从 F-Droid 安装 Termux，打开一次，运行 `termux-setup-storage`，在 `~/.termux/termux.properties` 里设置 `allow-external-apps=true`，并在安卓询问时授予运行命令的权限。如果 Termux 始终没有回应，错误信息现在会提到某些分支用了不同的包名——这种细节能省下一个晚上。

**会记事的下载。** 你选的最快镜像，现在真的会被使用——以前这个偏好只是存着，然后被客气地忽略。如果下载中断，下次会复用完好的暂存文件，而不是重新下载。一份小小的日志记下每次安装走到了哪一步，重试是接着讲故事，而不是从头再来。当镜像发来的文件大小与标称不符，提示现在会说：镜像可能只是更新了文件，并指引你换个源试试。

**助手会解释自己了。** `install_plugin` 工具先做预检，宁可有理有据地拒绝，也不半途失败。进度提示从第一个字节就开始出现，不再等到百分之二十。Termux 找不到软件包时，提示会解释可能是软件包列表过期了——而 Lucent 现在会自动刷新它。

**更安静的日志。** 操作日志在写入磁盘之前，会先把形似密钥的内容和网址里嵌的凭据涂掉。本来就不该被读到的东西，继续保持不被读到。

Lucent 的样子没有任何变化；只是工具箱如今像读过说明书一样行事。
